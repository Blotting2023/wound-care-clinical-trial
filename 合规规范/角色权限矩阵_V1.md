# 创面评估系统 V1 — 6 角色权限与数据视图矩阵

> 编制：WorkBuddy × 老胡 · 2026-09-07（W4.6 RBAC 数据隔离落地）
> 依据：
> - 《医疗器械临床试验质量管理规范》（NMPA 2022 年第 28 号）第八章 §57–§63 记录与数据要求
> - 《药物临床试验质量管理规范》（GCP 2020 修订版）§4 研究者 / §5 申办者 / §6 伦理委员会职责
> - 21 CFR Part 11（电子记录与电子签名）
> - GB/T 25000.51 + ALCOA+ 数据完整性原则（Attributable/Legible/Contemporaneous/Original/Accurate/Complete/Consistent/Enduring/Available）
> - 《个人信息保护法》（PIPL）最小必要 + 单独同意 + 境内存储

## 1. 总则（4 条不可破坏的红线）

1. **角色分离**：临床判断（创面打分/分级/入排医学判断）只能由研究者（PI / SubI）亲自完成；CRC 经 PI 书面授权可承担非医学判断的协调事务（合并用药/合并疾病/AE 列表/随访日期等），但 V1 demo 核心字段即创面打分，故 CRC 暂不录数据。
2. **数据最小化**：每个角色只能看到为履行职责所必需的数据；申办方只见统计聚合，不见个体；IRB 只看伦理相关文档。
3. **受试者身份三层保护**：姓名 → 病案号 → 鉴认代码（subjectCode，结构 `拼音首字母+4位序号`，如 `ZW0001`）。后两层对所有非研究方可见，最后一层对所有角色可见；真名仅 PI/SubI/Admin 可查（KMS 加密映射表）。
4. **写操作必留痕**：所有 PUT/POST/DELETE + 撤回 + 锁定 + 越权访问均写 `audit_log` 哈希链（`AuditOpType.accessDenied` 已写）。

## 2. 角色 × 权限 × 数据视图 一张表

| 角色 | 可见数据范围 | 可执行操作 | 工作台视图 | 数据呈现形态 |
|------|------------|-----------|-----------|------------|
| **PI 主要研究者** | 本中心全部患者（真名+病案号+鉴认代码）+ 全部评估 + 全部 eConsent + 全部审计日志 + 多中心汇总 | 新建/编辑患者、创面、部位、评估；**PI CRF 完成声明（PIN 二次鉴别）**；eConsent 双通道签字/撤回/审核 B 通道；试验方案/中心/器械配置；锁定 CRF；导出 PDF；查询 + 导出审计 | **临床工作台**：今日概览三宫格 + "+ 新建创面评估" + 最近评估列表（点击直达患者详情） | **完整原始数据**：姓名、病案号、创面图像、原始 CRF 字段、明文签名 |
| **SubI 副研究者** | 同 PI（含真名） | 同 PI，但不能做 PI CRF 完成声明锁定（PIN 锁定为 PI 独占） | **临床工作台**（同 PI，缺 PIN 锁定入口） | **完整原始数据**（与 PI 同） |

| **Sponsor 申办方** | **试验进度聚合统计**（受试者总数、已锁定评估数、进行中数、中心数）+ 审计日志汇总 + 试验器械台账 | 查阅统计、查询审计、PDF 导出；**不可查看受试者个体字段** | **监查统计视图**：4 宫格指标卡（受试者总数 / 已锁定 / 进行中 / 中心数）+ GCP 数据最小化原则提示 | **纯聚合数据**：所有个体字段（姓名/病案号/创面图像）均已隐藏；只见统计 |
| **IRB 伦理委员会** | **eConsent 队列**（鉴认代码 + 通道 + 中心编号 + 签署日期）+ SAE 报告 + 方案偏离记录 + 审计日志 | 审阅 eConsent（撤回权限）、SAE 审阅、查询审计 + 导出审计 | **伦理审阅视图**：待审 eConsent 列表卡 + "数据范围：知情同意书 + SAE 报告 + 方案偏离；不含临床评估明细" 提示 | **伦理相关数据**：受试者只见鉴认代码，不见姓名/病案号；评估明细隐藏 |
| **Admin 系统管理员** | 全部数据（含真名）+ 系统任务清单 | 多中心配置、eConsent 通道切换、器械追溯、角色分配、审计查询导出 | **系统管理视图**：多中心管理 / 角色分配 / 器械追溯 / 审计追踪 4 个任务入口卡 | **完整数据**（含真名，因系统运维必需），但**无临床数据录入入口** |

## 3. 法规依据逐条对齐

| 法规条款 | 对应 V1 实现 |
|---------|------------|
| GCP 2020 修订版 §4  研究者职责："临床判断必须研究者本人完成" | SubI 可代为操作但 PIN CRF 锁定仍为 PI 独占；CRC 无 `assessmentCreate`/`assessmentUpdate` 权限 |
| GCP 2020 修订版 §5  申办者职责："监查数据访问，但仅限履行职责所必需" | Sponsor 工作台只见聚合统计卡，不见个体受试者字段 |
| GCP 2020 修订版 §6  伦理委员会职责："审阅知情同意/SAE/方案偏离" | IRB 工作台替换为待审 eConsent 队列 + SAE 入口；不展示临床评估 |
| NMPA 2022 §57  记录要求："任何修改须留痕、可溯源" | 所有写操作 + 撤回 + 锁定 + 越权均写 `audit_log` SHA256 哈希链 |
| 21 CFR Part 11 §11.10(e)  审计追踪："记录创建/修改/删除的 who/when/before→after" | `audit_log` 字段：`operator_id/operator_name/operator_role/operator_ip/deviceFingerprint/op_type/before/after/reason/timestamp` |
| 21 CFR Part 11 §11.50/§11.70 电子签名 | A 通道笔迹 JSON + 设备指纹；B 通道纸质件拍照 + PI 审核；签名含义固定 |
| 21 CFR Part 11 §11.200 电子签名二次鉴别 | PI CRF 完成声明需 PIN（演示硬编码 '123456'，V4 接 OTP/生物识别） |
| PIPL §6  最小必要原则 | CRC/IRB/Sponsor 看到的姓名病案号脱敏为 "—" 或只见鉴认代码 |
| PIPL §40  医疗数据境内存储 + 加密 | 鉴认代码 + KMS 加密身份映射（V1 fake，V4 接入腾讯云 KMS） |

## 4. 端点权限矩阵（服务层 `_checkPermission` 兜底）

```
permission               PI  SubI CRC  Sponsor  IRB  Admin
─────────────────────────────────────────────────────────────
patient:create            ✅   ✅   ❌   ❌       ❌   ❌
patient:update_basic      ✅   ✅   ❌   ❌       ❌   ❌
patient:read_identity     ✅   ✅   ❌   ❌       ❌   ❌
assessment:create         ✅   ✅   ❌   ❌       ❌   ❌
assessment:update         ✅   ✅   ❌   ❌       ❌   ❌
assessment:lock           ✅   ❌   ❌   ❌       ❌   ❌   ← PI 独占
consent:sign              ✅   ❌   ❌   ❌       ❌   ❌
consent:withdraw          ✅   ❌   ❌   ❌       ✅   ❌
consent:configure         ✅   ❌   ❌   ❌       ❌   ❌   ← Admin 通过 centerManage
audit:read                ✅   ✅   ✅   ✅       ✅   ✅
audit:export              ✅   ❌   ❌   ❌       ✅   ✅
pdf:export                ✅   ✅   ✅   ✅       ❌   ✅
protocol:manage           ✅   ❌   ❌   ❌       ❌   ✅
center:manage             ✅   ❌   ❌   ❌       ❌   ✅   ← Admin 通过此切 consentMode
device:manage             ✅   ❌   ❌   ✅       ❌   ✅
```

> 服务端 `_checkPermission` 是权威；客户端 `PermissionService.can` 仅做菜单/按钮可见性的预过滤。任何越权操作均返回 403 + 写 `accessDenied` 审计。
