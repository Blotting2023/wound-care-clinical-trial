## 二、医疗器械 GCP 第八章「记录要求」核心条款摘录

> 来源：2022 年第 28 号公告附件原文（已交叉核对多个省级药监转发版）

**第五十七条**
> 医疗器械临床试验数据应当真实、准确、完整、具有可追溯性。医疗器械临床试验的**源数据**应当清晰可辨识，不得随意更改；确需更改时应当**说明理由，签名并注明日期**。

**第五十八条**
> 主要研究者应当确保任何观察与发现均正确完整地予以记录。**以患者为受试者的临床试验，相关的医疗记录应当载入门诊或者住院病历中。**

**第五十九条**
> 主要研究者应当确保按照申办者提供的指南，填写和修改**病例报告表**（CRF），确保 CRF 中的数据准确、完整、清晰和及时。CRF 中报告的数据应当与源文件一致。**CRF 中数据的修改，应当确保初始记录清晰可辨，保留修改轨迹，修改者签名并注明日期。**

**第六十条**（EDC 电子数据采集）
> 医疗器械临床试验中如采用电子数据采集系统，该系统应当：
> ① 经过可靠的**验证**；
> ② 具有完善的**权限管理**和**稽查轨迹**（audit trail）；
> ③ **可以追溯至记录的创建者、创建时间或者修改者、修改时间、修改情况**；
> ④ 所采集的电子数据**可以溯源**。

**第六十一条 — 必备文件**
> 医疗器械临床试验基本文件用于评价申办者、机构和主要研究者对规范的执行情况，**药品监督管理部门可以进行检查**。

**第六十二条 / 第六十三条 — 保存**
> 临床试验基本文件按阶段分三部分：**准备阶段 / 进行阶段 / 完成或终止后**。
> 临床试验机构应当保存临床试验基本文件至**医疗器械临床试验完成或者终止后 10 年**。基本文件在保存期间应**确保完整性，避免故意或者无意地更改或者丢失**。

## 三、ALCOA+ 数据完整性 9 项原则

> NMPA《医疗器械临床试验项目检查要点（2025.3）》第 5.1 节明确："原始病历中的数据，应当满足临床试验数据质量通用标准（ALCOA+）"。
> 基础 5 项 ALCOA 由美国 FDA 在 1990 年代提出；扩展 4 项（CCEA）由 EU GCP IWG 于 2010 年加入；2018 年起 ICH E6(R2)/E6(R3) 将其纳入 GCP 体系。

| # | 缩写 | 原则 | 对本 App 的具体含义 |
|---|------|------|---------------------|
| 1 | **A** | **Attributable** 可归因 | 每条数据能追溯到**具体的人**（操作员 ID + 角色 + 时间戳 + IP/设备指纹）。无共享账号。 |
| 2 | **L** | **Legible** 易读 | 数据在其保存期（≥10 年）内**清晰可读**。电子记录格式不可依赖将过时的系统。 |
| 3 | **C** | **Contemporaneous** 同步 | 数据在观察或操作发生**当时**记录。禁止事后追记、誊抄；如时间戳不在现场，要标"事后补录"并说明。 |
| 4 | **O** | **Original** 原始性 | 保留**第一手**数据或经核实的真实副本。创面照片、仪器原始输出、转录要标注"副本"并保留原始。 |
| 5 | **A** | **Accurate** 准确性 | 与临床事实完全一致。修改留痕、注明原因、责任人确认；禁止涂改；仪器需校准。 |
| +6 | **C** | **Complete** 完整性 | 必填项无空白；保留全部成功 + 失败 + 重复测试 + 元数据 + 审计日志。 |
| +7 | **C** | **Consistent** 一致性 | 跨表 / 跨中心 / 跨时间逻辑一致；时间戳顺序正确；CRF、数据库、报告互相一致。 |
| +8 | **E** | **Enduring** 持久性 | 用稳定介质和格式长期保存 ≥10 年；定期备份；不依赖将过时的专有格式。 |
| +9 | **A** | **Available** 可用性 | 监管核查时能**快速调阅**（索引清晰 + 受控权限 + 可导出 PDF/XML）。 |

**ALCOA++（可选）**：在 9 项之上再加 "T = Traceable 可追溯" — 体现为 EDC 系统从受试者 → CRF → 数据库 → 报告 → 监管提交的全链路追溯。

## 四、eCRF / CRF 填写指南要素（参考国家局 2016 范本 + 2022 GCP 第五十九条）

> CRF（Case Report Form 病例报告表）是临床试验中"采集数据"的核心载体。在 EDC 时代也叫 eCRF。
> 国家局 2016 年第 58 号通告给了 6 份范本：**伦理审查申请表 / 知情同意书 / CRF / 试验方案 / 试验报告 / 必备文件目录**，本 App 数据模型应向这 6 份范本对齐。

eCRF 字段级必须说明的：

1. **字段定义**（语义、单位、允许值、条件逻辑）
2. **源数据预期**（来自哪里 — 病历 / 检验报告 / 受试者日记 / 创面照片）
3. **缺失 / 不可用数据处理**（"未做 ND / 未知 UN / 不适用 NA" + 必填理由）
4. **日期时间格式**（ISO 8601 + 本地时区 + UTC 双存）
5. **测量单位**（与方案统一，cm、cm²、mg/dL、mmHg；不可混用）
6. **不良事件（AE）**（名称 MedDRA 编码 + 起止时间 + 严重程度 + 与器械关系 + 转归）
7. **合并用药 / 用械**（通用名或商品名 + 剂量 + 途径 + 起止 + 持续 / 停药）
8. **条件字段**（是否妊娠 / 是否入排标准 / 是否签知情）
9. **数据更正规则**（谁可以改、原因、痕迹、双签）
10. **审核与签名**（研究者复审 + 电子签 + 时间戳 + 签名的"含义"如"我已审核"）
11. **培训要求**（哪些角色必须先培训 / 重新培训时机）
12. **版本控制**（方案 / CRF / 填写指南任何改动都需受控、留痕、发布新版本号）

## 五、医疗器械试验特有的记录要求

### 5.1 试验器械追溯

> 国家局 2016 范本 + 2016/2022 GCP 第八十条 / 第二十九条

每条评估记录里**必须能溯到**：
- 试验器械名称 / 型号 / 规格
- 接收日期、批号、序列号
- 受试者分配（试验组 / 对照组 / 交叉）
- 每次使用日期 / 时间 / 状态（是否用械、何时回收）
- 剩余器械的处置（销毁 / 退回 / 留样）

### 5.2 受试者身份（鉴认代码 + 真实姓名 脱敏）

> 国家局 2016 范本 CRF 范本第 2 项

- 真实姓名**不进**系统主存储
- 用 **姓名缩写（拼音首字母）+ 4 位顺序号** 代替，例如 `ZW0001`（张伟-001）
- 真实姓名只在**加密的源数据映射表**（受试者鉴认代码 ↔ 真实身份）中保存
- 报告、SAE、统计数据库、申办者侧均**只**用鉴认代码

### 5.3 创面照片作为"影像源数据"

> 2022 GCP 第五十七条 + 检查要点 5.1.7"试验结果源数据的形式为电子照片、影像或者电子文档等，应当**完整保存源文件和关键过程文件**"

| 要求 | 落地细节 |
|------|---------|
| 完整保存 | **原始未压缩**（不可用微信 / jpg 高压缩重编码）+ 拍摄时间 + 拍摄设备 + 拍摄者 |
| EXIF 时间 | EXIF DateTimeOriginal 是"出片时间"最可信证据；护理员经常改系统时间，**EXIF 不能被客户端篡改** |
| 时间一致性 | 若同时用两台设备（拍照 + 录像），设备 NTP 同步；多张照片时间戳应**单调递增** |
| 拍摄参数 | 焦距、曝光、白平衡、校准卡（cm 刻度）— 这些是后续 AI / 第三方评审可信度的关键 |
| 隐私保护 | 患者面部 / 隐私部位不录入；如必须，用模糊化或裁剪 |
| 留存期 | **完成或终止后 10 年**；可刻盘 + 移动硬盘 + 云端冷存储三副本 |

### 5.4 严重不良事件（SAE）报告

> 2022 GCP 第三十一条 / 第三十二条 + 2020 GCP 第二十六条

- **24 小时内**研究者向申办者、机构、伦理委员会书面报告
- 致死 / 危及生命 SAE：申办者**7 日内**向所有参与机构通报
- 非致死 SAE：**15 日内**通报
- 报告内容用**受试者鉴认代码**，不用真实姓名
- 季度汇总报告 + 持续更新研究者手册

### 5.5 试验方案偏离

> 2022 GCP 第十五条（三）+ 2020 GCP 第二十条

任何对方案的偏离（含紧急情况下的偏离），**事后 24 小时内**以书面报告伦理委员会 + 机构 + 申办者。区分：
- 轻微偏离（不影响受试者权益和试验科学性）：每季度汇总
- 严重 / 持续偏离：立即报告

### 5.6 知情同意（电子化）

> 2022 GCP 第二十八条 + 第十四条

电子知情同意（eConsent）当前 NMPA **接受**但有特定要求：
- 须显示受试者能理解的图文
- 受试者手写签名（手写屏 / Apple Pencil）或电子签名
- **同时记录**受试者签名时间 + IP / 设备指纹 + 版本号
- 留一份副本给受试者（PDF / 微信推送）
- 受试者随时撤回的机制

### 5.7 数据留存与本地化

> 2022 GCP 第六十三条 + 个人信息保护法

- 医疗器械 GCP：**完成或终止后 10 年**（药物 GCP：批准上市后 5 年）
- PIPL：医疗数据属敏感个人信息，**应境内存储**；跨境需安全评估 / 标准合同 / 认证三选一
- 备份策略：3-2-1 原则（3 份数据，2 种介质，1 份异地）
- 销毁流程：留存期届满后按 SOP 销毁 + 销毁记录（日期、执行人、监督人）

## 六、电子签名要求（21 CFR Part 11 + 中国《电子签名法》）

> 21 CFR Part 11 是美国 FDA 对电子记录 / 电子签名的法规，ALCOA+ 的 "A (可归因)" 落地靠它。中国没有完全对应的法规，但《电子签名法》第十四条 "可靠的电子签名与手写签名或者盖章具有同等的法律效力"，结合 NMPA 对 EDC 系统的要求，**实际操作中需要同时满足 21 CFR Part 11 的技术要求和《电子签名法》的法律形式**。

| 维度 | 要求 |
|------|------|
| 唯一性 | 电子签名与签名人**唯一绑定**，不可借用、转让、复制 |
| 鉴别 | 签名时须**二次身份鉴别**（密码 + 短信 OTP / Touch ID / Face ID / 数字证书） |
| 含义 | 签名须声明含义（"我已审核" / "我已创建" / "我已批准" / "我同意"） |
| 时间戳 | 签名时记录**精确到秒**的时间戳（带时区） |
| 不可分离 | 电子签名与被签记录**链接**，无法剪切到另一条记录 |
| 不可篡改 | 签名后的记录**不能被修改**；修改需作废原签名后重签 |
| 审计 | 每次签名操作写审计日志（who, when, what, why） |
| 留档 | 签名记录随主数据一同留存 ≥10 年 |

## 七、EDC 系统（GCP 对 EDC 的强制要求）

> 2022 GCP 第六十条 + 2016 年第 114 号通告

| 维度 | 要求 |
|------|------|
| 系统验证 | 安装 / 升级 / 配置变更前**经过 IQ / OQ / PQ** 验证并留文件 |
| 权限管理 | 角色 × 操作矩阵；最小权限原则；离职 / 转岗及时撤权 |
| 审计轨迹 | 创建 / 修改 / 删除 / 查询 / 登录 / 注销 **全部记录**（who/when/what/from→to） |
| 数据导出 | 可导出 PDF（人读）+ CDISC SDTM / ODM-XML（机读）供统计 / 监管 |
| 时钟 | 服务器时间同步 NTP；客户端时间可作参考但**不能作为审计时间** |
| 备份 | 每日增量 + 每周全量；备份**异地存放**；每月做恢复演练 |
| 灾难恢复 | RPO ≤ 24h，RTO ≤ 4h（行业惯例） |
| 用户支持 | 7×24 工单系统 + 升级流程 |
| UAT | 正式上线前用预录入数据测试 ≥ 2 轮；UAT 报告归档 |

## 八、关键检查点（容易被 NMPA 检查员一票否决）

1. **CRF 数据的修改** — 是否留痕（前后值、改者、时间、原因）
2. **受试者鉴认代码** — 是否与真实姓名完全脱钩
3. **知情同意书版本** — 是否在每次修订后**让受试者重签**
4. **AE/SAE 报告时限** — 是否 24h 内完成首报
5. **试验器械追溯** — 每次使用是否有日期 / 时间 / 操作者
6. **研究者授权表** — 谁有权限做什么，是否有书面 delegation log
7. **源数据一致性** — 病历 / HIS / 检验报告 / CRF 是否能相互溯源
8. **必备文件** — 准备 / 进行 / 完成三阶段文件是否齐全且在保存地点
9. **数据库锁定（freeze）** — 是否有过 freeze/unfreeze 操作及理由
10. **数据留存 ≥10 年** — 备份介质是否仍可读；是否有定期恢复演练

## 九、与本项目直接相关的 5 个关键名词

| 名词 | 在本 App 的对应 |
|------|----------------|
| 试验方案（Protocol） | 申办者提供的方案文件；App 数据模型要关联 `protocolId + protocolVersion` |
| 病例报告表（CRF / eCRF） | App 里的"评估表"（创面 + NRS + VSS + 签名）— 必须可作 eCRF 用 |
| 源数据 | 创面原始照片 + NRS/VSS 量表的原始勾选 + 签名时的笔迹 / 按压力度 |
| 必备文件 | 伦理批件 / 方案 / CRF / 签知情同意书 / 监查报告... App 上传 + 版本管理 |
| 稽查轨迹 | App 后端每次数据操作的日志（who/when/what）— 监管检查时按时间倒放 |
